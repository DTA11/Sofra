# Plan novih recepata (Sofra recipe builder)

Owner's request (27. 11. 2026): 150–200 new recipes before the Claude plan ends (30. 11. 2026) — the most popular,
most delicious and healthiest dishes: more home cooking plus well-known dishes from around the world (ramen, noodles,
bowls, curries, tacos…). One batch per run of the scheduled task "Sofra recipe builder". Mark a batch DONE (date,
count, file) when it is pushed. If a batch is too big, split it (a/b) and finish part a fully.

## Rules for every batch (all of them, every time)
- Read README.md, ROADMAP.md, LEKTURA.md, js/data/index.js, js/data/ingredients.js, js/data/nutrition.js, js/planner.js (styleOf, SIDES, groupOf) and two existing recipe files before writing. Copy the exact object shape of existing recipes (id, cu, type, sub, main, meal, time, serves, kid, eq, eqOpt, ing, st, story, src, months, full, supa, grill…).
- **No duplicates**: before writing, list all existing recipe names/ids (node, see test below) and skip any dish that already exists under another name. Replace a skipped dish with another popular dish of the same kind.
- **Names and stories never mention countries, regions, cities or nationalities** (no „japanski“, „indijski“, „meksički“, „tajlandski“…; dish names like Ramen, Pho, Tacos, Bibimbap, Shakshuka, Falafel, Chili con carne are fine). „Bečka šnicla“ is the only exception and already exists. cu/reg are hidden data only.
- Never "JNA" in the UI („Vojnička kuhinja“). No sources shown (src stays hidden: `src: T` = trad). No brand or producer names (no „Sriracha“, „Philadelphia“, „Nutella“…: say „ljuti umak od čilija“, „krem sir“).
- New ingredients: entry in js/data/ingredients.js (bs, en, section, season, perishability like the others) AND js/data/nutrition.js (values per 100 g from a reliable food table, same format). One name per ingredient, ingredient names without brackets. Prefer ingredients a normal supermarket has; give a common swap in the note where something is hard to find (e.g. miso, fish sauce, gochujang).
- Text: bs (ijekavica) + en. Lektura terms: češanj/češnjevi, isijeci/isjeckaj, kašika/kašičica, šaka, prstohvat, luk na rebarca, tava, rerna, tečnost, preljev; the app says „ti“; „jelovnik“ never „plan“. Steps short and clear, timers on waiting/cooking steps. Story 1–2 sentences, no places.
- Amounts and times realistic for a home kitchen, serves 4 unless the dish is naturally different. Every ingredient that matters gets an amount (no `null` except salt/pepper/spices to taste), so nutrition is counted.
- Mix in every batch: at least a third of dishes grade A–B, some kid-friendly (`kid: 1`), some quick (≤ 30 min), some meat-free/posno where natural. Check grades with nutrition.js after writing.
- New file per theme (e.g. js/data/recipes-world.js, js/data/recipes-home2.js, js/data/recipes-sweet3.js), imported in js/data/index.js and added to FILES in sw.js. Bump VERSION in sw.js once per run.
- **World style** (batch 3, before any world dish): new planner style `svijet` — i18n style label bs „Iz svijeta (rezanci, bowl, curry, tacos)“ / en „From around the world (noodles, bowls, curries, tacos)“, default weight 1 in store.js defaults (existing users get it via the defaults merge), styleOf in index.js maps cu `svijet` (hidden) to it. Desserts and breakfasts from the world just use their normal type. Add the matching filter/kuhinja chip only if the existing UI has one per style.
- Add taste/wording choices that a native speaker should check to LEKTURA.md under „Novi recepti (builder)“ — at least one line per batch: „batch N: X recipes, new texts — needs native-speaker review“.
- Tests before push (all): Node (copy js/ to a temp folder with package.json {"type":"module"}, mock localStorage and navigator with Object.defineProperty, store.load(); generate jelovnici for all ranges dish/day/week/month and modes normal/ramazan/katolicki/pravoslavni, no errors; every recipe has bs+en name, ≥2 steps, story, all ingredient ids exist in ING and nutrition; grades of all OLD recipes unchanged vs. the previous commit; print grades of the new ones). Playwright/Chrome (/usr/bin/google-chrome, playwright in /opt/npm-tools, locale bs-BA, serve via context.route(); close the quick guide via document.querySelector('#modal.open [data-w="x"]').click(); at 390 px check the empty jelovnik #/plan, #/recipes and 3 new recipe pages for overflow incl. text overflowing inside elements; search finds 3 new dishes by name without diacritics). Never use sed with the /e flag on sw.js. No local http server.
- Update README (recipe count, new file in Struktura) and ROADMAP (#9 photo count total, recipe count). Commit author Claude <noreply@anthropic.com>, push to main.
